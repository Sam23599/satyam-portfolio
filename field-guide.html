01RETRIEVAL / AI
PROJECT BLUEPRINT

Proof, please.

A document assistant that shows its working.

Ask a question about a dense policy PDF. Get an answer with the exact table row, page citation, or an honest “I don't have enough evidence.”

PythonFastAPIRAGPostgreSQLRedisAWS S3
Open the build brief +

Build the smallest credible version

Ingest table-heavy PDFs while preserving headers, units and page locations. Combine keyword and vector retrieval, rerank candidates, and return source-linked answers with an abstention path.

The engineering story

Content hashes prevent duplicate ingestion. Version documents and invalidate affected caches. Enforce tenant filters before retrieval. Treat retrieved instructions as untrusted input.

Evidence to publish

Create 100 manually reviewed questions, including unanswerable and misleading-table cases. Compare retrieval recall@k, numeric answer accuracy, citation correctness, p50/p95 latency and cost per answer against a baseline. Publish measured results, dataset limitations and failure cases.

02EVENT SYSTEMS
PROJECT BLUEPRINT

Delivery, eventually.

A webhook platform built for bad days.

Deliver events when services time out, messages arrive twice, and a downstream API decides to take a small vacation.

FastAPIPostgreSQLSQSRedisDocker
Open the build brief +

Build the smallest credible version

Accept an event, write it with an outbox record in one transaction, queue deliveries, sign webhooks and expose delivery history. Add exponential backoff with jitter, dead-letter handling and controlled replay.

The engineering story

Use at-least-once delivery with idempotent consumers; define the deduplication window. Bound concurrency per tenant and prevent a failing destination from starving others. Start with SQS; compare Kafka only when replay or ordered partitions justify it.

Evidence to publish

Inject timeouts, duplicate messages and worker crashes. Report accepted versus delivered events, duplicate side effects, queue age, recovery time and throughput on explicitly documented hardware.

A demo worth clicking

A “break the receiver” switch: deliveries fail, retries back off, the receiver recovers, and the audit trail explains every attempt.

03VOICE / ORCHESTRATION
PROJECT BLUEPRINT

Hold that thought.

A voice-agent runtime that knows when to stop.

A small provider-neutral runtime for streaming speech, LLM responses, interruptions, and a clean handoff to a human.

Python asyncioSTT / TTS / LLMRedisWebSocketAWS
Open the build brief +

Build the smallest credible version

Implement one STT, LLM and TTS adapter behind typed interfaces. Stream audio, support barge-in with cancellation, bound queues and record the session state machine. Add a second provider to prove the interface works.

The engineering story

Separate transport from orchestration. Define timeout budgets, backpressure, reconnect behavior and cleanup. Prevent cancelled responses from speaking or executing stale tools. Use synthetic calls for the public demo.

Evidence to publish

Measure time to first audio, interruption-to-silence latency, queue growth and concurrent-session resource use. Test disconnects, provider stalls and repeated interruptions with reproducible traces.

A demo worth clicking

Interrupt a speaking agent and inspect the timeline showing STT, model generation, TTS and cancellation.
